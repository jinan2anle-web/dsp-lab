# 数字信号处理实验二三 · 内容讲解

> 这份文件只讲**这个实验在做什么**，不含署名，可直接外发。
> 对应课程：数字信号处理，实验二「语音信号的频域特征分析」＋ 实验三「基于 DTW 的孤立字语音识别」（讲义第 8–14 页）。

---

## 一句话

让计算机听懂一个人念的 **0–9 十个中文数字**，并且**中间的算法全部自己写代码**实现，不许调用现成的语音库。

整件事分两步：先把一段声音变成一串能比较的数字（实验二），再拿这串数字去和模板比对、判断是哪个数字（实验三）。

---

## 一、数据：100 条录音

| 项目 | 值 |
| --- | --- |
| 内容 | 中文数字「0」到「9」各念 10 遍 |
| 数量 | 10 类 × 10 条 = 100 条 |
| 格式 | WAV，16 kHz 采样、单声道、16 bit PCM |
| 时长 | 每条 1.5 s |
| 说话人 | 全部同一人、同一次录制 |
| 划分 | 每类前 5 条（编号 01–05）用来**建模板**，后 5 条（06–10）用来**测试**，共 50 条测试 |

划分是锁死的，一旦换了数据，所有数字都要重跑。

## 二、实验二：把一段声音变成一串数字

### 为什么要做这一步

原始波形是一万多个采样点，直接比较没有意义——同一个人念两遍「3」，波形长度和起伏都不同。所以需要一种**能反映"音色"而与说多快、说多响关系不大**的表示。这就是 MFCC（梅尔频率倒谱系数），语音识别里用了四十年的经典特征。

### 怎么做：六步，每步都自己写

```
录音波形
  ↓ ① 预加重           H(z) = 1 − 0.97·z⁻¹，抬高高频
  ↓ ② 分帧 + 加窗      25 ms 一帧（400 点），帧移 10 ms（160 点），汉明窗
  ↓ ③ 自写基 2 FFT     400 点补零到 512 点做 FFT（512 = 2⁹，便于基 2 运算）
  ↓ ④ 功率谱           E(i,k) = |X_i(k)|²
  ↓ ⑤ Mel 滤波器组     24 个三角滤波器，按人耳的梅尔刻度分布
  ↓ ⑥ 对数 + DCT       得到 13 维 MFCC（含 c0）
特征矩阵
```

两条硬要求：

1. **FFT 必须自己写**（位倒序 + 蝶形递推），不许用 `numpy.fft` / `scipy.fft`。写完之后要和 `numpy.fft` 逐点对拍，最大误差 **5.86×10⁻¹⁴**，远小于 10⁻¹⁰ 的判据——这一步是专门为了防"看起来像频谱但其实算错了"。
2. **不许用任何第三方语音库**（如 librosa）。梅尔滤波器、DCT 全部手写。

### 出来是什么样

一条 1.5 s 的录音 → **148 帧 × 13 维**的矩阵。

可以把它想象成一张"声音的照片"：横轴是时间（148 个时刻），纵轴是 13 个描述音色的数。

## 三、实验三：认出这是哪个数字

### 核心困难

同一个字，念快念慢不一样。第一遍「3」占 60 帧，第二遍可能占 75 帧。**长度不同就没法逐帧一一对应着比**。

### 解决办法：DTW（动态时间规整）

DTW 允许把两条序列"拉伸/压缩"后再对齐，找出累计距离最小的那条对齐路径。三条规则写死了：

- 只能从三个方向走到当前格：(i−1, j)、(i−1, j−1)、(i, j)
- 起点 D(1,1) = 第一格的帧距，之后逐格递推
- 越界取 +∞（不能取 0，否则路径会贴着边白走）
- 帧距 d = (1/K)·√Σ(xₖ−yₖ)²，其中 **K 是特征维数 13，不是帧数**

### 识别流程

```
训练阶段：50 条训练录音 → MFCC → 模板库（每类 5 条）
测试阶段：一条测试录音 → MFCC → 和 10 个类的所有模板挨个算 DTW 距离
                              → 每类取"最近的那个模板"的距离当得分
                              → 得分最小的类 = 识别结果
```

用"取最小"而不是"取平均"：模板是同一个字的不同念法，能对上任何一条就算认出来，平均反而会把一条好的和四条差的混在一起。

### 端点检测（可选开关）

录音开头有 0.35 s 的静音，末尾也有空白。端点检测用**双门限（短时能量 + 过零率）**把真正的语音段切出来，只留中间那 0.665 s 左右。

它是一个**可关的开关**，不是必须步骤——主结果用整段 1.5 s，端点段只作为对照。实测两者总数同为 40/50（其中 12 条判决互换、类间得失恰好抵消），端点段把判决时间从 28.4 s 压到 7.5 s（约 3.8 倍），因为要比对的帧数从 148 降到几十。

## 四、最后的结果

50 条测试录音：

| 条件 | 正确数 | 准确率 |
| --- | --- | --- |
| **主结果**（整段 + 5 条模板 + 原始 MFCC） | 40 / 50 | **0.800** |
| 每类只用 1 条模板 | 30 / 50 | 0.600 |
| 每类用 3 条模板 | 37 / 50 | 0.740 |
| 加倒谱均值归一化（CMN） | 41 / 50 | 0.820 |
| 改用端点段输入 | 40 / 50 | 0.800 |

三个能站得住的结论：

1. **模板数是第一位的**。每类 1 → 3 → 5 条，识别率 0.600 → 0.740 → 0.800 单调上升。模板越多，覆盖的语速和发音变化越广。
2. **窗函数和预加重不是瓶颈**。矩形窗 / 汉明窗 / 汉宁窗 × 预加重开与关，六组结果全落在 0.780–0.800，只差 1 条样本。所以这份数据上不必在这两个参数上纠结。
3. **难的是个别易混的类别**。10 个类里 5 个满分，「6」和「8」只有 0.40 召回，错例集中在 1↔0/6、2↔3、4↔5、8↔2/3 这些近音数字上。有意思的是，换一套完全不同的特征（时域统计量）做同样的实验，「6」的召回也是 0.40——说明不是特征选得不好，是这一类字本身就容易混。

### 已知局限

- 只有一位说话人、一次录制，0.800 **不能外推到多人场景**。
- 测试集只有 50 条，1 条样本就值 2 个百分点，所以 0.780 / 0.800 / 0.820 之间的差别都在统计噪声内，不能据此说"某个做法更好"。
- DTW 没有加斜率约束，对端点误差比较敏感。

## 五、怎么复现

```bash
pip install -r requirements.txt

# 一条命令跑完全部：自测 → 实验二消融与图 → 实验三识别与消融 → 图
python -m scripts.run_all          # 约 2–3 分钟

# 起一个图形界面，选一条录音就能看到波形、MFCC 和识别结果
python -m dsp.app
```

跑完的产物分三处：

| 目录 | 内容 |
| --- | --- |
| `report/tables/` | 所有数字（CSV），每个报告里的数都能在这里查到出处 |
| `report/fig/` | 5 张自己画的图 + 界面截图，300 dpi |
| `report/evidence/` | 自测输出（FFT 对拍、MFCC 形状、DTW 手算表）与运行日志 |

`report/tables/traceability.csv` 是一张"数字 → 出处文件 → 复现命令"的对照表，核对时用它会很快。
